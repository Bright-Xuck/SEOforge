# Purpose

Forge exists to become the world's most capable autonomous Website Operations Platform for continuously improving websites through deterministic automation, provider integrations, and AI-assisted reasoning.

Forge is not an SEO tool.

Forge is not a chatbot.

Forge is not a WordPress plugin.

Forge is an AI Operating System for websites.

SEO is one capability.

Accessibility is one capability.

Performance is one capability.

Security is one capability.

Content is one capability.

Conversion Optimization is one capability.

The system's purpose is to understand a website, determine what limits its success, plan improvements, execute approved work, verify the results, and continuously learn from previous executions.

---

# Mission

Create an AI platform that performs website work with the consistency, reasoning, and quality of a senior engineer, SEO consultant, UX designer, accessibility expert, and content strategist while remaining fully transparent, explainable, and under human control.

Forge should eliminate repetitive website work while improving the quality of decisions.

---

# Long-Term Vision

Forge should eventually become the operating system used by developers, agencies, businesses, and independent creators to manage every aspect of a website.

Instead of hiring multiple specialists, users should assign a mission.

Example:

> Increase organic traffic by 30%.

Forge determines what work must be completed.

Example:

- Technical SEO improvements
- Content improvements
- Internal linking
- Navigation changes
- Accessibility fixes
- Performance optimization
- Structured data improvements
- Conversion improvements

Forge creates the execution plan, performs approved work, verifies results, and continuously improves future recommendations.

# Core Philosophy

Forge is built around five principles.

## 1. Intelligence Before Automation

Automation without reasoning creates mistakes.

Forge should understand before acting.

Every action should be supported by evidence.

---

## 2. Human Approval

Forge never owns production.

Forge recommends.

Forge drafts.

Forge explains.

Humans approve.

Human approval is required before any production-changing operation unless explicitly overridden by the owner.

---

## 3. Explainability

Every recommendation must answer:

- What changed?
- Why?
- What evidence supports it?
- What impact is expected?
- What confidence does Forge have?
- How can the change be reverted?

No recommendation should exist without explanation.

---

## 4. Continuous Learning

Forge remembers previous work.

Future recommendations should improve because Forge understands:

- previous audits
- accepted recommendations
- rejected recommendations
- website preferences
- writing style
- business goals
- historical performance

Forge becomes more valuable the longer it is used.

---

## 5. Modular Intelligence

Forge is composed of independent capabilities.

Capabilities can be added, removed, replaced, upgraded, or disabled without affecting the rest of the platform.

No capability should require changes to the core architecture.

# Design Principles

## Simplicity

Simple architecture scales.

Complexity must always be justified.

---

## Replaceability

Every provider can be replaced.

Every plugin can be replaced.

Every capability can be replaced.

Vendor lock-in is unacceptable.

---

## Composability

Small capabilities should compose into larger workflows.

Forge should never depend on massive monolithic components.

---

## Scalability

Forge Version 1 should naturally evolve into Version 20.

Large architectural rewrites should be avoided.

---

## Observability

Every important action should be observable.

Logs.

Events.

Execution history.

Reasoning.

Metrics.

Failures.

Nothing important should happen silently.

# Decision Framework

When multiple implementation options exist, choose the option that best satisfies the following priorities:

1. Simplicity
2. Maintainability
3. Extensibility
4. Testability
5. Explainability
6. Performance
7. Developer Experience
